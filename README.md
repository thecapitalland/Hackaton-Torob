# 🌱 تربچه (Torobche)

**دستیار خرید حضوری در تهران** — از انتخاب محله و جست‌وجوی محصول تا مقایسه و برنامهٔ خرید.

تربچه یک اپلیکیشن وب فارسی و موبایل‌فرست (React + LangGraph + FastAPI) است که با داده‌های واقعی ترب
(دیتاست خام: ۲۲۵٬۹۰۳ کالا · ۳۳۱٬۵۰۶ آفر · ۶٬۴۷۶ فروشگاه؛ خروجی اسلیم: **۴۰٬۱۲۰ کالا · ۱۱۵٬۱۸۵ آفر · ۲٬۷۵۱ فروشگاه**)
کار می‌کند و فقط چیزی را نشان می‌دهد که **واقعاً در دیتابیس هست**.

---

## 🎬 جریان کار

```
انتخاب موقعیت: GPS / جست‌وجوی محله / انتخاب روی نقشه
   ↓
پیام کاربر
   ↓  understand (LLM + قوانین)         ← بودجه، دسته، محله، قسطی، امروز؟
   ↓  clarify (interrupt + چیپ)         ← حداکثر ۳ سؤال، آخرین گزینه «مهم نیست»
   ↓  search (SQL روی catalog.db)
   ├─→ recommend        کارت‌های بهترین / اقتصادی / پریمیوم + کارت «بورس تخصصی»
   └─→ out_of_catalog   «در داده‌های ترب نبود» + گزینه‌های واقعی + نکته‌های عمومی
   ↓  select_product → find_stores       فروشگاه‌ها + نقشه + امتیاز شفافیت
   ↓  verify (interrupt تأیید کاربر)     پیام شبیه‌سازی‌شده → خواندن پاسخ → رتبه‌بندی دوباره
   ↓  trip                                برنامهٔ رفتن + پلن ب + کافهٔ نمونه + چک‌لیست
```

## ✨ قابلیت‌ها

- **چت فارسی RTL** با استخراج نیاز (بودجه «۴ میلیون» → ۴٬۰۰۰٬۰۰۰ تومان، محله، قسطی، امروز).
- **سه کارت پیشنهاد**: 🏆 بهترین · 💸 اقتصادی · 💎 پریمیوم — با «چرا این؟» و هشدار قیمت غیرعادی.
- **کارت بازار تخصصی**: «🏬 بورس این کالا در تهران: بورس جمهوری–حافظ» با آمار واقعی از داده‌ها
  (مثلاً هدفون: ۱۵۷ فروشگاه در بازار از ۲۴۴ فروشگاه شهر) و برچسب «اطلاعات عمومی» برای ساعت کاری.
- **جست‌وجوی چت‌محور**: ابتدا «کجایی؟»؛ موقعیت با GPS، نام محله یا انتخاب روی نقشه ثبت می‌شود. تغییر موقعیت، فروشگاه‌های همان مدل را دوباره رتبه‌بندی می‌کند.
- **پیشنهاد محصول**: کارت‌ها در دو ستون دسکتاپ و یک ستون موبایل‌اند؛ خلاصهٔ دسته، بودجه، محله و شعاع را می‌توان با پیام طبیعی اصلاح کرد.
- **انتخاب فروشگاه**: فهرست در گفتگو و نقشه به‌شکل تصویر بندانگشتی است؛ با لمس آن نقشه باز می‌شود. فاصلهٔ شعاعی ۲، ۵، ۱۰ کیلومتر یا کل تهران (پیش‌فرض) قابل انتخاب است.
  نقشه (react-leaflet/OSM)، نشان «باز است تا ۲۰:۳۰»، فاصلهٔ هوایی،
  پاساژ/طبقه، پرداخت حضوری، و **نشان شفافیت** (۵ نقطه) — به‌جای امتیاز جعلی فروشنده.
- **پیام‌رسانی با تأیید انسان (HITL)**: قبل از هر پیام یک `interrupt` لاگراف، پیش‌نویس پیام قابل ویرایش،
  سپس پاسخ‌های **شبیه‌سازی‌شده** (موجود / قیمت جدید / ناموجود / بی‌پاسخ) و رتبه‌بندی مجدد.
- **نقشه و مسیر (Update #1)**: ریسپانسیو کامل (موبایل تک‌ستون، تبلت پنل تاشو، ۱۲۸۰+ دوپنله ۴۰/۶۰)،
  فاصله و زمان پیاده روی کارت‌ها («فاصلهٔ تقریبی» در حالت fallback)، خط مسیر روی نقشه،
  جئوکدینگ معکوس («شما نزدیک … هستید») و دیپ‌لینک‌های «مسیریابی در نشان/بلد» —
  کلید `NESHAN_API_KEY` فقط سمت بک‌اند است و نبودش به fallback کامل برمی‌گردد.
- **برنامهٔ رفتن**: خط زمانی، پلن ب، کافه (نشان → OSM → لیست محلی + برچسب منبع)، چک‌لیست و لینک‌های «نشان» و «بلد».
- **Out-of-catalog**: اگر کالایی در داده‌ها نبود، صادقانه می‌گوید، گزینه‌های واقعی از داده‌ها نشان می‌دهد
  و نکته‌های عمومی را با برچسب «اطلاعات عمومی، نه از داده‌های ترب» می‌آورد — بدون ساختن مغازه یا قیمت.
- **محله‌ها بدون کلید API**: حدود ۶۰ محلهٔ تهران در `backend/app/data/tehran_neighbourhoods.json` با نام‌های جایگزین و مختصات fallback تعریف شده‌اند؛ جست‌وجوی Neshan در صورت وجود کلید به این نتایج افزوده می‌شود.
- **مقایسهٔ انتخابی**: ۲ تا ۴ کارت را انتخاب کن؛ قیمت کمینه/میانه/بیشینه، تعداد فروشگاه‌ها و نتیجهٔ بصری در «تحلیل ایجنت» نمایش داده می‌شود. مسیر متنی «X یا Y؟» هم فعال است.
- **کشوی «🧠 چطور به این نتیجه رسیدم؟»**: هر نود گراف با خلاصه و زمان پاسخ.
- با `LLM_MODE=off` **کاملاً کار می‌کند** (حالت قاعده‌محور).

## 🧭 جریان و رابط جست‌وجو

- شروع با پیام خوشامدگویی و «کجایی؟»؛ موقعیت فعلی، تایپ محله یا انتخاب نقطه روی نقشه.
- محله‌ها با تطبیق نام و alias resolve می‌شوند؛ «سعادت آباد» و «سعادت‌آباد» به یک نقطه می‌رسند. اگر Neshan API key نباشد، دیتاست محلی در محدودهٔ تهران پاسخ می‌دهد.
- شعاع روی فهرست و نقشه اعمال می‌شود؛ «کل تهران» حالت پیش‌فرض است. اگر فروشگاهی در شعاع نبود، دکمهٔ افزایش شعاع در دسترس است.
- متن تایپ‌شده بر بودجه یا محلهٔ قبلی اولویت دارد؛ اصلاح‌هایی مانند «بالای ۱۰ میلیون هم بگرد» یا «تو جمهوری هم بگرد» همان گفتگو را ادامه می‌دهند.

تصاویر smoke در هر دو اندازهٔ ۱۴۴۰×۹۰۰ و ۳۹۰×۸۴۴: [docs/ux](docs/ux/)

## 🤝 چانه‌زنی با داده (Phase 2)

برای هر فروشگاهِ همان کالا، آمار واقعی آفرها ساخته می‌شود؛ هیچ عددی از LLM نمی‌آید:

| مفهوم | قاعده |
|---|---|
| برچسب منصفانه | `گرون` اگر قیمت > میانه + ۱۰٪ · `خوب قیمت` اگر ≤ چارک اول · بقیه `معمولی` · تک‌فروشگاه `تک‌عرضه` |
| هدف چانه | چارک اول (Q1) رُندشده به ۱۰ هزار تومان، اما نه کمتر از قیمت خود فروشگاه |
| سقف خرید | میانهٔ همان کالا، رُندشده به ۱۰ هزار تومان |
| اهرم چانه | اول فروشگاه هم‌پاساژ، بعد ارزان‌ترین، بعد نزدیک‌ترین — با فاصله و میزان صرفه‌جویی واقعی |
| پیام فروشنده | یک سؤال مؤدبانه با «هدف» از پیش محاسبه‌شده؛ کاربر قبل از ارسال تأیید می‌کند |
| پاسخ فروشنده | شبیه‌سازی قطعی: پذیرش هدف / پیشنهاد متقابل / بدون تغییر؛ قیمت مذاکره‌شده پارس و در رتبه‌بندی جایگزین می‌شود |

- پنل هر فروشگاه: نشان انصاف، خط میانه، هدف/سقف/درصد صرفه‌جویی، متن آمادهٔ چانه و دکمهٔ کپی.
- هشدار «ارزان‌تره»: «۱۲۶ متر اون‌ورتر «نیکورا ویوان» ۱٬۶۹۰٬۰۰۰ تومان» + دکمهٔ **اضافه به مسیر**.
- صندوق پاسخ‌ها: نشان `✅ پذیرفت` / `🤝 پیشنهاد متقابل` و قیمت مذاکره‌شده؛ برنامهٔ رفتن هم قیمت مذاکره‌شده را نشان می‌دهد.
- LLM فقط اجازهٔ بازنویسی ۲–۳ خط چانه را دارد؛ اگر عدد یا نام فروشگاهی خارج از payload بسازد،
  خطوط قطعی جایگزین می‌شوند. با `LLM_MODE=off` همهٔ این‌ها بدون LLM کار می‌کند.

### اصلاحات QA2

- نقشهٔ دسکتاپ (≥۱۲۸۰px): `invalidateSize` روی mount/resize/ResizeObserver و ارتفاع کامل wrapper؛ کاشی‌ها و مارکرها بعد از تغییر اندازه هم دیده می‌شوند.
- برگهٔ نقشهٔ موبایل: بستن با ✕ (`aria-label="بستن"`) و کلید Escape؛ `role="dialog"` و `aria-modal`.
- طبقهٔ فروشگاه‌ها با ارقام فارسی («طبقه ۱»، «طبقه منفی ۱») در کارت، پاپ‌آپ نقشه و مسیر.
- Out-of-catalog: تیتر با «واژهٔ کالا»ی تمیزشده نمایش داده می‌شود، نه جملهٔ کامل («زعفران» نه «زعفران می‌خوام»).

### اصلاحات QA3

- **B1 پیام به‌ازای هر فروشگاه:** در برگهٔ اجازه، هر فروشگاه متن خودش را دارد (textarea جدا) و سؤال هدف فقط با هدفِ همان فروشگاه ساخته می‌شود؛ فروشگاهی که هدف ≥ قیمت خودش (مثل تک‌عرضهٔ ۱٬۳۹۰٬۰۰۰) دیگر «با ۲٬۷۴۰٬۰۰۰ حضوری می‌دید؟» نمی‌شنود. پیامِ هر فروشگاه مستقیماً به صندوق همان فروشنده می‌رود.
  نمونه: [qa3-permission-per-shop.png](docs/phase2/qa3-permission-per-shop.png)
- **B2 «برنامهٔ رفتن رو بچین» همیشه در دسترس:** وقتی هیچ فروشگاهی تأیید نکرد ولی از هشدار «ارزان‌تره» فروشگاهی به مسیر اضافه شده، هم صندوق (بنر کهربایی) و هم بخش فروشگاه‌ها دکمهٔ برنامهٔ رفتن دارند. خلاصهٔ برنامه دیگر ادعای «موجودیش تأیید شده» بی‌دلیل نمی‌کند («موجودیش هنوز تأیید نشده، بپرس بعدش»).
  نمونه‌ها: [qa3-no-confirm-plan-button.png](docs/phase2/qa3-no-confirm-plan-button.png) و [qa3-trip-without-confirmation.png](docs/phase2/qa3-trip-without-confirmation.png)
- **B3 «چرا این؟» صادقانه:** برچسب «ارزان‌ترین قیمت» فقط روی خودِ ارزان‌ترین می‌نشیند؛ بقیه «قیمت مناسب» می‌گیرند.
- **B4 خط محل:** وقتی فروشگاه پاساژ ندارد، دیگر «🏬 · طبقه ۲» رندر نمی‌شود (اجزای خالی با « · » حذف می‌شوند).
- **B5 پلن ب تکراری نیست:** پلن ب از فروشگاه‌هایی بیرون از همین توقف‌ها انتخاب می‌شود و تعداد تأییدشده اولویت دارد.
- **اختیاری:** فروشگاه‌هایی که قیمت‌شان زیر ۵۰٪ میانهٔ بازار است (خطای داده) دیگر به‌عنوان اهرم چانه پیشنهاد نمی‌شوند؛ به‌جایش نزدیک‌ترین فروشگاه واقعیِ ارزان‌تر معرفی می‌شود.

### مقایسه (P3: «X یا Y کدوم بهتره؟» و انتخاب ۲ تا ۴ کارت)

- **تشخیص:** «هدفون یا هندزفری کدوم بهتره؟»، «X بهتره یا Y»، «فرق X و Y» و حتا «X یا Y»ی کوتاه موبهمهٔ خرید (بدون فعل خرید، تا ۶ کلمه). سؤال‌های عادی با «یا» (مثل «هدفون R50i یا زیر ۴ میلیون») مقایسه حساب نمی‌شوند.
- **جدول به‌ازای هر طرف** از دادهٔ واقعی ترب: بازهٔ قیمت + میانه، تعداد مدل، تعداد فروشگاه و تعداد نزدیک (تا ۵ کیلومتر از محل کاربر؛ بدون ثبت محل = ۰). بهترین مدل هر طرف هم زیر جدولش می‌آید.
  نمونه: [compare-desktop.png](docs/phase2/compare-desktop.png) و [compare-mobile.png](docs/phase2/compare-mobile.png)
- **نتیجه با برچسب «تحلیل ایجنت»:** مشروط و صادقانه — متن نتیجه با «تصمیم با تو» می‌بندد؛ با LLM، متن نتیجه بازنویسی می‌شود ولی هر عددی خارج از اعداد جدول رد می‌شود و قالب قطعی جایگزین می‌گردد؛ با `LLM_MODE=off` همان قالب قطعی کار می‌کند.
- **نشانه‌های برند:** «آدیداس/ادیداس» (نرمال‌سازی آ↔ا) هم پیدا می‌شود — اگر همهٔ مدل‌های یک برند تک‌فروشگاهی باشند، جست‌وجو یک پله با `min_shops=1` ادامه می‌یابد. برای برند بدون دسته (نایک) فقط دستهٔ غالب نتایج نگه داشته می‌شود تا جوراب و کفش با هم قاطی نشوند.
- **هشدار کپی روی همهٔ نتایج** (نه فقط ۸ مدل اول) می‌خوانَد؛ چک‌لیست حضوری دارای «جعبهٔ اصلی و کد مدل را با سایت سازنده تطبیق بده» هم هست. اگر کاربر محل نداده باشد، «نزدیک تا ۵ کیلومتر» به‌جای صفر «—» نشان می‌دهد.
- **پس از یک مقایسه، پیام عادی بعدی از متن تازه بازسازی می‌شود** و پاسخ تایپی به سؤال در انتظار (مثل تایپ «جمهوری» برای سؤال محله) همان سؤال را به‌جای رهاشدن حل می‌کند؛ یعنی «سامسونگ یا شیائومی کدوم بهتره؟» → «گوشی سامسونگ تا ۶۰ میلیون» → «جمهوری» به کارت محصول می‌رسد، نه out_of_catalog.
- **هشدار کپی:** اگر در عنوان یکی از طرف‌ها نشانهٔ «کپی/درجه یک/replica/فیک» باشد، هشدار احتیاط + چک‌لیست حضوری (فاکتور، گارانتی/هولوگرام، تست حضوری) نمایش داده می‌شود.
- **دو طرف قابل لمس‌اند:** کلیک روی هر طرف جدول، مستقیماً وارد فلؤ عادی همان کالا می‌شود (کارت کالا → فروشگاه‌ها)؛ کارت مقایسه بعد از آن پاک می‌شود و در پیام‌های بعدی دوباره ظاهر نمی‌شود.

## 🚀 اجرا

### ۰) از صفر (Run from scratch)

از کلون تمیز تا اجرا — بدون هیچ کلید API.

**ویندوز (PowerShell):**

```powershell
# 1) venv + نصب وابستگی‌ها
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt

# 2) ساخت دیتابیس از دیتاست خام ترب (به shops.csv / products.csv / offers.csv نیاز دارد)
python backend\scripts\build_catalog.py --src <مسیر دیتاست torob-dataset> --out data\catalog.db
python backend\scripts\build_markets.py --catalog data\catalog.db --out data\markets.json

# 3) بیلد فرانت‌اند — خروجی مستقیماً در static/ ساخته می‌شود (همان‌جا که بک‌اند سرو می‌کند)
cd frontend
npm install --cache ..\.npm-cache
npm run build
cd ..

# 4) اجرا بدون LLM و دموِ تکرارپذیر
$env:PYTHONIOENCODING="utf-8"
$env:LLM_MODE="off"; $env:DEMO_MODE="1"; $env:DEMO_NOW="2026-10-22T15:00:00+03:30"
.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

**لینوکس / macOS:**

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r backend/requirements.txt
python backend/scripts/build_catalog.py --src /path/to/torob-dataset --out data/catalog.db
python backend/scripts/build_markets.py --catalog data/catalog.db --out data/markets.json
(cd frontend && npm ci && npm run build)
PYTHONIOENCODING=utf-8 LLM_MODE=off DEMO_MODE=1 DEMO_NOW=2026-10-22T15:00:00+03:30 uvicorn backend.app.main:app --port 8000
```

→ `http://127.0.0.1:8000/`

نکته‌های بازتولیدپذیری:

- `vite.config.ts` مقدار `build.outDir` را روی `../static` گذاشته است؛ بنابراین `npm run build` دقیقاً همان جایی
  می‌نویسد که FastAPI سرو می‌کند و کپی دستی لازم نیست. اگر فقط بیلد قدیمی `frontend/dist` موجود باشد،
  `STATIC_DIR` به‌طور خودکار به آن fallback می‌کند.
- ورودی `build_catalog.py` باید سه CSV رسمی `shops.csv`، `products.csv` و `offers.csv` را داشته باشد.
  شمارش مورد انتظار بعد از اسلیم: **۴۰٬۱۲۰ کالا / ۱۱۵٬۱۸۵ آفر / ۲٬۷۵۱ فروشگاه**
  (دیتاست خام: ۲۲۵٬۹۰۳ / ۳۳۱٬۵۰۶ / ۶٬۴۷۶ — کاهش عمدی برای زیر ۱۵۰ مگابایت شدن دیتابیس و حذف پرت‌هاست).
- `build_markets.py` فایل `data/markets.json` را **بازنویسی** می‌کند؛ تغییرات دستی در آن (بازارهای بیرونی،
  ساعت‌های کاری) باید در `MARKET_DEFINITIONS` / `EXTERNAL_MARKETS` داخل اسکریپت اعمال شود، نه فقط در JSON.

بعداً وقتی کلید BoxAPI و (اختیاری) کلید نشان (`NESHAN_API_KEY`) را در `.env` گذاشتی،
یک بار `python backend/scripts/smoke_llm.py` را بزن تا base_url/model درست پیدا شود،
`LLM_MODE=on` را در `.env` بگذار و همان دستور uvicorn را اجرا کن. نبودِ کلید نشان باعث
fallback کامل (فاصلهٔ تقریبی/کافهٔ محلی) می‌شود — اپ هرگز نمی‌شکند.

### ۱) دیتابیس را بساز

```bash
python -m venv .venv
.venv\Scripts\activate            # ویندوز
pip install -r backend/requirements.txt

python backend/scripts/build_catalog.py \
  --src /path/to/torob-dataset \
  --out data/catalog.db

python backend/scripts/build_markets.py \
  --catalog data/catalog.db --out data/markets.json
```

`build_catalog.py` چاپ می‌کند: قیمت‌های خارج از بازه حذف شدند، آفرهای پرت (مثل ۲۲٬۹۵۰٬۰۰۰ برای R50i)
حذف شدند، برای هر (کالا، فروشگاه) فقط ارزان‌ترین آفر ماند و در صورت لزوم دیتابیس تا زیر ۱۵۰ مگابایت
کوچک شد.

> فایل `data/catalog.db` داخل گیت نیست (حجمش زیاد است)؛ با همین دستور ساخته می‌شود.

### ۲) بک‌اند

```bash
cp .env.example .env      # کلید BOXAPI را داخلش بگذار
uvicorn backend.app.main:app --reload --port 8000
```

`GET http://localhost:8000/api/health` →
`{"ok":true,"catalog_rows":{...},"llm_mode":"on","tz":"Asia/Tehran"}`

```bash
cd frontend

```

## 🔐 قوانین سخت (که در کد رعایت شده‌اند)

1. هر کالا/فروشگاه/قیمت نمایش‌داده‌شده **از دیتابیس** می‌آید؛ LLM هیچ‌وقت چیزی نمی‌سازد.
2. هیچ پیامی بدون تأیید کاربر (`interrupt`) ارسال نمی‌شود.
3. همهٔ پاسخ‌های فروشنده با برچسب «پاسخ شبیه‌سازی‌شده» نمایش داده می‌شوند.
4. شماره‌های تلفن دیتاست (جعلی) هرگز نمایش یا استفاده نمی‌شوند.
5. وضعیت باز بودن فقط `open | closed | unknown` (منطقهٔ زمانی تهران)؛ نبودِ ساعت ⇒ «نامشخص».
6. داده‌های بیرون از ترب با برچسب «اطلاعات عمومی» مشخص می‌شوند (بازار رضا اصلاً استفاده نمی‌شود).
7. برنامه با `LLM_MODE=off` هم کامل کار می‌کند.

## 🎥 سناریوی دمو

۱. «یه هدفون بلوتوثی خوب می‌خوام زیر ۴ میلیون، امروز حضوری نزدیک فردوسی»
۲. یک چیپ: «آره، قسطی»
۳. سه کارت (بهترین = R50i) + کارت «بورس جمهوری–حافظ، ۱۵۷ فروشگاه»
۴. فروشگاه‌ها: نشان‌های «گرون/معمولی/خوب قیمت» + خط میانه برای هر ردیف
۵. انتخاب آوان آران (گران) → پنل چانه با هدف ۲٬۷۴۰٬۰۰۰ و اهرم «نیکورا ویوان» → **اضافه به مسیر**
۶. انتخاب دو فروشگاه دیگر → برگهٔ اجازه با سؤال هدف → تأیید → پاسخ شبیه‌سازی‌شده
۷. صندوق پاسخ‌ها: آوان «🤝 پیشنهاد متقابل ۳٬۳۰۰٬۰۰۰» و مهریسا «✅ پذیرفت ۲٬۷۴۰٬۰۰۰» → برنامهٔ رفتن
۸. (اختیاری) «زعفران و ادویه» → کارت «در داده‌های ترب نبود» با تیتر تمیز

با `DEMO_MODE=1` و `DEMO_NOW=2026-10-22T15:00:00+03:30` نتیجه‌ها کاملاً تکرارپذیرند.
